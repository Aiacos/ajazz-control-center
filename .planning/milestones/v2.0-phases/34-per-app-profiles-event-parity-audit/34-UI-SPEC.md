# Phase 34 — UI Design Contract

> Visual and interaction contract for the Phase 34 UI surfaces. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope is intentionally small.** Phase 34 is predominantly backend (window-watcher, event-parity audit). The only UI surfaces are (1) an **assign-profile-to-app** surface (APROF-03) and (2) a **Wayland/GNOME capability-warning chip** (APROF-03). This contract pins those two surfaces to the project's *existing* Qt 6 / QML + Material design system (`Theme.qml`). It does NOT introduce a new design system, and it does NOT expand scope beyond these two surfaces.

______________________________________________________________________

## Design System

| Property              | Value                                                                                                                                                                                              |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tool                  | none (Qt 6 / QML + `QtQuick.Controls.Material`; not a web/shadcn stack)                                                                                                                            |
| Preset                | not applicable                                                                                                                                                                                     |
| Component library     | In-house QML component set under `src/app/qml/components/` (Card, PrimaryButton, SecondaryButton, EmptyState, PageHeader, Toast, Notification) over `QtQuick.Controls.Material`                    |
| Token source of truth | `src/app/qml/Theme.qml` — central design-token singleton (consumed as `Theme.*`). All colors, spacing, radius, typography, motion, elevation MUST come from this singleton. No hardcoded literals. |
| Icon library          | Project icon font / bundled SVG resources (no new icons required for this phase)                                                                                                                   |
| Font                  | Application default (system UI font); sizes/weights from the `Theme` typography ramp below                                                                                                         |

**shadcn gate:** Not run. This is a C++/Qt/QML desktop app, not a React/Next.js/Vite project. The shadcn initialization gate and registry safety gate do not apply.

**Canonical pattern to mirror:** `src/app/qml/SettingsPage.qml`. The new assign-profile surface is a settings/editor sub-surface and MUST match it structurally: a section `Label` heading (`Theme.typeTitleMedium`, `Accessible.role: Accessible.Heading`) followed by a `Frame` card (`background: Rectangle { color: Theme.tile; border.color: Theme.borderSubtle; border.width: 1; radius: Theme.radiusMd }`) wrapping a `ColumnLayout`. The warning chip mirrors the trust-chip in `src/app/qml/LoadedPluginsPage.qml:168-209`.

## Spacing Scale

Pinned to the existing `Theme` spacing tokens (a 4-point scale; `Theme.spacingMd` is 12, not 16 — do NOT re-introduce a 16 "md"). Use the token names, never raw px.

| Token | `Theme` name      | Value | Usage in this phase                                                        |
| ----- | ----------------- | ----- | -------------------------------------------------------------------------- |
| xs    | `Theme.spacingXs` | 4px   | Chip inner gap, icon-to-text gap                                           |
| sm    | `Theme.spacingSm` | 8px   | Compact row spacing, chip vertical padding                                 |
| md    | `Theme.spacingMd` | 12px  | Default element spacing inside the card; chip horizontal padding           |
| lg    | `Theme.spacingLg` | 16px  | Card-to-card gap, page `ScrollView` margins, section spacing               |
| xl    | `Theme.spacingXl` | 24px  | Major section break (between "Per-app profiles" and any following section) |

| Radius | `Theme` name     | Value | Usage                                              |
| ------ | ---------------- | ----- | -------------------------------------------------- |
| sm     | `Theme.radiusSm` | 4px   | Inner controls                                     |
| md     | `Theme.radiusMd` | 6px   | Card / Frame corners (matches SettingsPage Frames) |
| lg     | `Theme.radiusLg` | 8px   | Larger surfaces if needed                          |

Exceptions:

- **Capability-warning chip** uses a pill radius of `12` (matches the existing trust-chip in `LoadedPluginsPage.qml`; not a `Theme.radius*` token because pills use height/2). Chip preferred height `24`. This is the one sanctioned non-token radius, consistent with the established chip convention.
- **Minimum interactive target** `Theme.minTouchTarget` (44px) applies to the add/remove-mapping buttons and the app-name combo/field (GUIDELINES ≥44×44).

## Typography

Pinned to the `Theme` Material 3 typography ramp (use the `type*` token objects; bind `pixelSize`, `weight`, `letterSpacing`). Exactly the four roles this phase needs:

| Role             | `Theme` token           | Size | Weight       | Usage in this phase                                                            |
| ---------------- | ----------------------- | ---- | ------------ | ------------------------------------------------------------------------------ |
| Section heading  | `Theme.typeTitleMedium` | 16px | Medium (500) | "Per-app profiles" section `Label` (Accessible.Heading)                        |
| List-row title   | `Theme.typeTitleSmall`  | 14px | Medium (500) | App-name in each mapping row                                                   |
| Body             | `Theme.typeBodyMedium`  | 14px | Normal (400) | Profile-name value, control labels, descriptive text                           |
| Helper / caption | `Theme.typeBodySmall`   | 12px | Normal (400) | Explanatory note under the section; warning-chip detail text; empty-state body |

Chip label uses `Theme.fontXs` (12px) at `Font.DemiBold` to match the existing trust-chip label exactly.

Line height: QtQuick `Text` default (the `Theme` ramp deliberately elides `lineHeight`; do not override). Heading/body cadence follows Material defaults.

## Color

Pinned to `Theme` tokens. The 60/30/10 split maps onto the existing dark-first palette (also valid in light mode — all tokens are polarity-aware via `Theme`).

| Role                   | `Theme` token                                                                                      | Usage                                                                    |
| ---------------------- | -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| Dominant (60%)         | `Theme.bgBase`                                                                                     | Page background of the settings/editor surface                           |
| Secondary (30%)        | `Theme.tile` (border `Theme.borderSubtle`)                                                         | The mapping card / Frame surface and rows                                |
| Accent (10%)           | `Theme.accent`                                                                                     | Primary action only (see reserved-for list); focus rings                 |
| Warning (semantic)     | `Theme.chipBgWarning` / `Theme.chipBorderWarning` / `Theme.chipFgWarning` (amber `#f59e0b` family) | Capability-warning chip ONLY — a degraded-capability state, not an error |
| Destructive (semantic) | `Theme.errorAccent` (`#e34c4c`)                                                                    | Remove-mapping confirmation affordance only                              |
| Muted text             | `Theme.fgMuted`                                                                                    | Helper/caption text                                                      |
| Primary text           | `Theme.fgPrimary`                                                                                  | Headings and row titles                                                  |

**Accent reserved for:** the primary "Add mapping" / save action and keyboard focus rings only. Accent is NOT applied to every interactive control (rows, combos, secondary buttons use neutral `Theme.tile`/`SecondaryButton` styling). The warning chip is amber (`chipBgWarning`), NOT accent — it is a capability degradation, not a brand highlight or an error.

**Why warning (amber), not error (red):** the Wayland/GNOME limitation is a *graceful degradation* (the watcher still runs, profiles still switch manually), not a failure. It uses the warning chip family, matching the "self-signed plugin" severity tier — never the red error family.

## Component & Interaction Contract (phase-specific)

This section is the executor's authoritative interaction spec. It supplements the token tables above.

### Surface 1 — Assign-profile-to-app (APROF-03)

| Aspect         | Contract                                                                                                                                                                                                                                                               |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Location       | A new section within the existing settings/editor area, matching `SettingsPage.qml` structure (section `Label` + `Frame` card). Layout shape is at executor discretion (per CONTEXT.md) as long as it mirrors the SettingsPage card pattern and uses `Theme.*` tokens. |
| Card surface   | `Frame` with `background: Rectangle { color: Theme.tile; border.color: Theme.borderSubtle; border.width: 1; radius: Theme.radiusMd }`                                                                                                                                  |
| Row content    | App-name input/selector + profile selector + remove affordance per mapping; new-mapping action labelled `Add mapping`.                                                                                                                                                 |
| Empty state    | Use the `EmptyState` component (`title` + `body` from the copywriting table) when there are zero mappings.                                                                                                                                                             |
| Profile source | The profile selector lists existing profiles (writes to `Profile::applicationHints`). When zero profiles exist, show the "No profiles available" error-state copy instead of an empty combo.                                                                           |

### Surface 2 — Capability-warning chip (APROF-03)

| Aspect     | Contract                                                                                                                                                                                                                                               |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Pattern    | Mirror the trust-chip in `LoadedPluginsPage.qml:168-209`: a `Rectangle` pill, `Layout.preferredHeight: 24`, `radius: 12`, `border.width: 1`, centered `Text`.                                                                                          |
| Colors     | `color: Theme.chipBgWarning`, `border.color: Theme.chipBorderWarning`, text `color: Theme.chipFgWarning`. Amber/warning family ONLY.                                                                                                                   |
| Label      | `Limited on this desktop` at `Theme.fontXs` / `Font.DemiBold`.                                                                                                                                                                                         |
| Detail     | `ToolTip` on hover carrying the full capability-warning detail copy above.                                                                                                                                                                             |
| Visibility | Shown ONLY when the active `IActiveWindowWatcher` backend reports no foreground-window capability (degraded Wayland/GNOME path). Hidden when the capability is present (no warning = positive signal, matching the trusted-chip-invisible convention). |
| Placement  | Adjacent to the "Per-app profiles" section heading so the user sees the limitation in the same context as the mapping controls.                                                                                                                        |

### Mandatory: debug-channel addressability (project hard rule, VERIF-01)

Every interactive control AND the warning chip MUST set `objectName`. Required `objectName`s (executor may extend, must not omit):

| Control                         | `objectName`                                                                                                                  | Debug-channel expectation                                                                                                                                                               |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Add-mapping action              | `addAppProfileMappingButton`                                                                                                  | `qml.click` / `qml.invoke` triggers add-mapping flow                                                                                                                                    |
| App-name input (per row)        | `appProfileAppNameField`                                                                                                      | `qml.set` writes the app name                                                                                                                                                           |
| Profile selector (per row)      | `appProfileProfileSelector`                                                                                                   | `qml.get`/`qml.set` reads/writes the chosen profile                                                                                                                                     |
| Remove-mapping action (per row) | `removeAppProfileMappingButton`                                                                                               | `qml.click` removes the row                                                                                                                                                             |
| Capability-warning chip         | `waylandCapabilityWarningChip`                                                                                                | `qml.get` returns its `visible` state AND a non-empty warning text property (e.g. `warningText`) — CONTEXT.md explicitly requires the chip's `qml.get` to return non-empty warning text |
| Warning text property           | expose `warningText` (or chip `ToolTip.text`) addressably so the live verification can assert non-empty content without hover |                                                                                                                                                                                         |

> **Harness note (CLAUDE.md):** `qml.invoke toggle` / `qml.click` fire `onClicked` but NOT a `Switch`/`CheckBox` `onToggled`. Use plain `Button`/`SecondaryButton` for actions (as PI-02 did), not a `Switch`, so the add/remove actions are drivable end-to-end from `scripts/ajazz-debug`.
