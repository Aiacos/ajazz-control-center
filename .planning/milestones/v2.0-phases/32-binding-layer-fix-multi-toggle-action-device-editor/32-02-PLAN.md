<objective>
BIND-04/05 Multi Action dispatch: when a key/dial bound to a Multi Action is pressed, run the
firing binding's `instance.children` sequentially with inter-step delay, reusing the existing
`ActionEngine` chain walk (no new runner). Built on Wave-1's `instanceChildrenToChain` adapter.

Purpose: Phase 31 stored children model-only; the existing `multiactions` handler decodes a FLAT
JSON array, not `binding.instance.children`. The new dispatch resolves the typed children at the
seam where the firing `Binding` is in scope (`StreamDockInputService::dispatch`), because the
opaque `BuiltinHandler(string_view)` cannot see the binding (RESEARCH Findings 2 + 3, Q4).
Output: Multi Action wired through the input-service seam + a registry classification entry + tests.
</objective>
