<objective>
Wire `profileChanged` to the bridge's `populateContextsForActivePage` so a drag-drop binding registers an `ActionContext` immediately, and extend `populateContextsForActivePage` to enumerate `touchZones.onTap` (registered under controller="Encoder" per the locked touch-tap lookup). This is what makes a dropped plugin action actually fire — the highest-risk integration wave.

Purpose: Today `profileChanged` is connected only to repaint/LunBo slots, NOT to the bridge. A drop commits the binding and repaints the LCD but never registers a context, so a later `input.encoder` hits a dead lookup and the plugin never receives `dialRotate`/`dialDown`. And `populateContextsForActivePage` never enumerates `touchZones` at all (doubly broken for touch-zone drops). PLUGIN-19's ActionContext-registration requirement closes here.
Output: A public `activeDeviceId()` accessor, the guarded `profileChanged` connection, touch-zone enumeration, and bridge unit tests.
</objective>
