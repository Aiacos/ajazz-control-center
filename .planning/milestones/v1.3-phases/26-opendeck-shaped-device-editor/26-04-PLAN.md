<objective>
Land the new geometry-driven `DeviceView.qml` editor and its companion
components (`EncoderDial`, `TouchStripLane`, `ActionLibraryPane`), extend
`KeyCell.qml` with `DropArea` + `Drag.active` for the new drag-drop grammar
(D-09), atomically replace the existing `KeyDesigner.qml` with the new
editor in `ProfileEditor.qml`'s LCD-key branch, and delete `KeyDesigner.qml`
in the SAME commit per the CLAUDE.md hard-replacement atomic constraint.
This implements REQ-26-B per 26-SPEC.md and resolves the visual + interaction
contract pinned in 26-UI-SPEC.md.

Purpose: REQ-26-B is the core deliverable of Phase 26. The current
`KeyDesigner.qml` is a single generic `GridLayout columns=root.gridColumns`
(lines 40-176) — no encoder visualisation, no touch-strip drop target.
Operator UAT 2026-05-28 reported "no LCD entry in app UI, only Dial"
(GAP-25B). OpenDeck's `DeviceView.svelte` (RESEARCH.md §2.2) shows the
canonical pattern: three stacked rows (`rows × columns` keys → encoders
row → touchpoints row), single `Key` delegate discriminated by controller
type, drag-drop via HTML5 MIME (`application/x-ajazz-action` for
library→cell, `application/x-ajazz-binding` for cell-to-cell).

This plan ports the OpenDeck pattern to Qt 6 / QML (patterns-only reuse;
no direct code copy per RESEARCH.md §8 risk 1) while honoring all 13
locked CONTEXT.md decisions (D-01..D-13) and the UI-SPEC.md tokens.

Output:

- 4 new QML files (`DeviceView.qml`, `EncoderDial.qml`, `TouchStripLane.qml`,
  `ActionLibraryPane.qml`).
- 1 extended QML file (`KeyCell.qml`).
- 1 modified QML file (`ProfileEditor.qml` LCD-key Loader swap).
- 1 deleted QML file (`KeyDesigner.qml`).
- 1 modified CMake file (`src/app/CMakeLists.txt`) registering the new
  QML files in the AjazzControlCenter QML module + a `device-layouts/`
  resource glob in preparation for Plan 26-06.

The atomic-commit constraint (CLAUDE.md): `KeyDesigner.qml` deletion +
`DeviceView.qml` first compile + `ProfileEditor.qml` LCD-key branch flip
MUST land in ONE git commit. No interim broken-editor state.

This plan is the heaviest in Phase 26. To stay within the ~50% context
budget, layout JSONs and photo assets are NOT in this plan (deferred to
Plan 26-06 which runs concurrently with QML test plan 26-05 in Wave 4).
DeviceView ships with the outline-frame fallback path (D-07) wired
unconditionally for v1; once Plan 26-06's per-SKU layout JSON for AKP05E
lands, the photo path engages without further DeviceView edits (the file
is a runtime lookup against a `qrc:/qt/qml/AjazzControlCenter/device-layouts/`
path).
</objective>
