<objective>
Wire the inbound half of the bridge: connect `SdPluginServer::actionReceived(pluginUuid, action)`
to a dispatch slot that, for the visual action family (`setImage`/`setTitle`/`setState`/`setBG`/
`setFeedback`/`setText`), resolves the action's `context` against the registry, ENFORCES that the
context belongs to the sending plugin, and drives the Phase-14 `StreamDockControlService` to paint
the resolved 1-based key. `setImage` is the PLUGIN-10 core: strip `data:` -> decode (19-01 helper) ->
hand the `QImage` to `assignKeyImage` (the backend + `image_pipeline` do the scale + JPEG q85 encode;
NO second encode path). On decode failure paint a crash-free placeholder and send no failure event
(§5). Construct the bridge in `Application` after the server + control + input services and verify
end-to-end with a loopback `QWebSocket` client + the Phase-14 control-service spy. PLUGIN-10.

Purpose: PLUGIN-10 — the inbound (plugin -> device) round-trip, including the context-ownership
access-control mitigation.
Output: the `onAction`/`onSetImage`/`paintPlaceholder` bridge logic + the Application wiring + the
loopback-client -> control-spy e2e tests.
</objective>
