<objective>
Implement the `passHello` + salt/challenge authentication handshake on `SdPluginServer` (PLUGIN-05):
after `registerPlugin`, the host generates a random per-connection salt, stores it on the connection,
and sends `passHello` with NESTED `authentication:{challenge, salt}` (per CONTEXT — spec §4.5's
top-level salt is explicitly superseded). When a password is configured, the plugin replies
`{event:"authentication", challenge: sha256(password+salt)}`; the host verifies against
`QCryptographicHash::Sha256(password + salt)`, accepting on match and **rejecting after 5 bad
attempts** by closing the socket. Default (no password) = passHello sent, connection accepted
(loopback-only by design; NO TLS — an accepted constraint, not a gap).

Purpose: PLUGIN-05, the security-sensitive slice. A test-only password setter makes
`PluginAuthTest::rejectsAfter5BadAttempts` exercisable (production default is no-password-accept).

Output: extended `PluginConnection` auth state, a test-only `setPasswordForTesting`, the passHello
emit + authentication verify + reject-after-5 logic, and the §9-named Catch2 auth cases.
</objective>

<interfaces>
From src/app/src/sd_plugin_server.hpp — extend the struct (17-02 already added sendEvent/socketForUuid):
  struct PluginConnection {
    QString uuid;
    QWebSocket* socket{nullptr};
    QString salt;            // NEW: hex-encoded random, per connection
    int authAttempts{0};     // NEW: bad-challenge counter; reject at >=5
    bool authenticated{false};
  };

Auth wire shapes (LOCKED per CONTEXT — the tests assert these exact shapes):
Host -> plugin passHello (NESTED salt; spec §4.5 top-level is SUPERSEDED):
{"event":"passHello","payload":{"device":<id>,"deviceInfo":{...},
"authentication":{"challenge":\<host-side, empty when no password>,"salt":<hex>}}}
(Emit via the 17-02 sendEvent seam: sendEvent(uuid, "passHello", payloadObj).)
Plugin -> host authentication reply:
{"event":"authentication","challenge": sha256(password + salt)}
Host verify: QCryptographicHash::hash((password.toUtf8()+saltHex.toUtf8()), Sha256).toHex()
The "+" is UTF-8 bytes of password concatenated with UTF-8 bytes of the hex salt string
(17-RESEARCH A3 — this defines OUR contract; real-plugin interop verified in Phase 18/25).

Constants: kMaxAuthAttempts = 5 (reject at the 5th bad attempt -> close socket).
Salt: QRandomGenerator::system() filling a QByteArray, .toHex() (17-RESEARCH A2). QUuid is an
acceptable fallback if the QRandomGenerator fill API differs.

\<threat_model>

## Trust Boundaries

| Boundary                                 | Description                                                                    |
| ---------------------------------------- | ------------------------------------------------------------------------------ |
| unauthenticated plugin -> SdPluginServer | A connecting client is untrusted until (optionally) it completes the challenge |
| brute-force attempts -> auth verify      | Repeated bad challenges cross here                                             |
| network interface -> server bind         | LAN must never reach the server (loopback-only, unchanged)                     |
