<objective>
Unify the Property Inspector's settings context so the PI and the plugin read/write ONE `plugin_settings_store` record. Today Inspector.qml's `_contextUuid()` returns `profileId + selection-label` while the plugin + wire use `device#page#controller#row#column` (ContextRegistry::deriveContextId), so PI-written and plugin-read settings land in DIFFERENT files. Fix Inspector.qml to pass the WIRE context id as `contextUuid`, and unify PIBridge's per-context persistence onto the shared `plugin_settings_store` keyed by that same wire context.

Purpose: PLUGIN-22 — make the Property Inspector usable end-to-end. The plugin->PI relay (`relayToPropertyInspector` -> `deliverToPropertyInspector`, commit 361cc77) only becomes meaningful once both sides share one record.

Output: Inspector.qml passes the wire context; PIBridge persists/reads via plugin_settings_store; a live PI round-trip proven (set in PI -> plugin receives + on-disk record matches).
</objective>
