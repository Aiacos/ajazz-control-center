finally drives the already-byte-tested `Akp05Device` backend. It holds the active

`open()` left the panel dark and assigned images never reached the device. This
service is the reuse surface Phases 15 (input), 16 (controls/persistence), and 19
(plugin bridge) all build on, so its shape is the load-bearing decision here.

CRITICAL keyIndex convention: the `Akp05Device` backend is 1-BASED (keys 1..KeyCount,
KeyCount=10) — `keyIndexInRange` rejects 0 and >10. The `IDisplayCapable` doxygen says
"zero-based" but the SHIPPING backend is 1-based and capture-verified; the backend wins
(CLAUDE.md RE-is-source-of-truth). Pass 1-based indices. The repaint path must map the
profile's key indices to the device's 1-based scheme — confirm the profile key-index
base by reading profile usage before writing the loop; if profile keys are 0-based,
translate (key + 1). Document the chosen mapping in the SUMMARY.

backend per VID/PID. HOLDING the returned shared_ptr is what keeps the single HID handle
open across event-loop turns (Pitfall 2).

## Trust Boundaries

| Boundary                                 | Description                                                                                                                                                                                                                  |

| app service -> USB device (held handle)  | The held shared_ptr<IDevice> spans event-loop turns; a device yank mid-burst must degrade safely (zombie-contract no-op).                                                                                                    |
| device input/profile data -> setKeyImage | Oversized/malformed images could desync firmware.                                                                                                                                                                            |
