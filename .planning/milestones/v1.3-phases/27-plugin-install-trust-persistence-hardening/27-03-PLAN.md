<objective>
Persist per-plugin user-intent enable/disable across restart. Today `discover()` returns every `*.sdPlugin/` manifest and the launch loop spawns them all unconditionally; the only disable map (`m_disabled`, `plugin_manager.cpp:545-557`) is session-only and is set on the 3-in-30s crash path. A user who disables a plugin must have it stay disabled on the next launch. Add a positive disabled-set in QSettings consulted by the spawn path, plus `setPluginEnabled(id, bool)` to toggle it.

Purpose: Closes the second half of PLUGIN-15 (persistence). Runs in Wave 3; depends on Plan 02 (rediscover) only because both edit `plugin_manager.cpp` — sequencing them avoids same-wave file overlap and lets rediscover() also consult the persisted disabled-set introduced here.

Output: A QSettings-backed disabled-set (`plugins/disabled/<pluginId>`); a spawn-skip in the discover/spawn flow AND in `rediscover()`; `PluginManager::setPluginEnabled(id, bool)` that writes the setting and tears down (disable) or spawns (enable) the live plugin; a hermetic restart-survival Catch2 test using `QStandardPaths::setTestModeEnabled`.
</objective>
