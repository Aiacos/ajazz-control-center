<objective>
Add `PluginManager::rediscover()` — an idempotent re-scan that spawns ONLY newly-added plugins and never tears down or double-spawns a live one — and wire it to `PluginCatalogModel::installFinished` so a plugin installed from the GUI runs live with NO app restart. Today `discover()` runs once at launch (`application.cpp:801`); installing a plugin lands it on disk but nothing re-scans, so the runtime requires a restart. This is the #1 "installabile" gap from the install-epic reconciliation.

Purpose: Closes half of PLUGIN-15 (the install→run loop). Runs in Wave 2 parallel with Plan 05 (the PLUGIN-17 concurrency regression test, which is tests-only and shares no source files). Plan 03 (persisted enable/disable, the other half of PLUGIN-15) also edits `plugin_manager.cpp`, so it is sequenced into Wave 3 to honor the zero-file-overlap rule for same-wave parallel plans.

Output: `PluginManager::rediscover()` (idempotent, diffs the dir scan against `m_live` keys); an `installFinished` → `rediscover()` connection in `Application`; a hermetic Catch2 test proving only-new-plugins-spawn with no double-spawn.
</objective>
