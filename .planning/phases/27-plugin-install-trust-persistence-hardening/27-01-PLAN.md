<objective>
Split the plugin manifest verifier's single `Refused` verdict into **Unsigned** (manifest carries no Ed25519 signature block) and **Tampered/Refused** (signature block present but cryptographically invalid). This is the security-critical CR-01 deliverable: a tampered package is an attack and must ALWAYS quarantine even when the user consents to unsigned installs; an unsigned package is a developer sideload that may be installed with explicit consent.

Purpose: Without this split, the GUI install-from-file path cannot safely offer "install unsigned with consent" because it cannot tell a sideloaded developer plugin from a tampered attack package. This plan is Wave 1 and blocks the trust UX (Plan 03) which surfaces the consent affordance.

Output: `SignatureState { None, Valid, Invalid }` on `ManifestVerifyResult`; `VerifyVerdict::Unsigned` distinct from `Refused`; `installFromFile` promotes Unsigned-with-consent and quarantines tampered unconditionally; Catch2 tests asserting "tampered refused even with consent" and "unsigned installs with consent / refused without".
</objective>
