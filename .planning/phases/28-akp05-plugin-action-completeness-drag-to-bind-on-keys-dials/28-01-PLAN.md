<objective>
Extend the plugin manifest data model so installed plugins expose their full action surface, and add the `affordanceMask` normalizer that downstream drop-gating consumes. This is the foundation wave: every later plan reads the new struct fields and the new helper.

Purpose: Today `PluginAction` lacks `VisibleInActionsList` (so hidden vendor actions leak into the library) and the Encoder/multi-state/Settings model (so dial actions cannot be modelled), and there is no controller->affordance helper (so drop targets cannot gate). PLUGIN-18 (completeness foundation) + PLUGIN-20 (full model + affordance helper) start here.
Output: Extended `plugin_manifest.{hpp,cpp}`, new Catch2 tests, two Wave-0 fixtures.
</objective>
