<objective>
Extend `DeviceDescriptor` with four additive zero-default geometry fields,
populate them on every in-scope LCD-key SKU row in
`src/devices/streamdeck/src/register.cpp`, and land the REQ-26-D Catch2
regression test that fails CI if a future LCD-key descriptor row lands
without geometry data. Implements REQ-26-C and REQ-26-D per 26-SPEC.md.

Purpose: the new `DeviceView.qml` editor (Plan 26-04) reads per-SKU geometry
from `DeviceDescriptor` to discriminate the three stacked rows
(`keyRows × keyColumns` LCD-key grid, encoder-dial row when
`encoderCount > 0`, touch-strip-zone row when `touchZoneCount > 0`). Current
descriptor has only `keyCount` + `gridColumns`; the new editor cannot
infer rows correctly without `keyRows` (AKP815 is 5×3 portrait,
`keyCount=15 / gridColumns=3` → would render 5×3 by accident; AKP153 is
3×5 landscape, `keyCount=15 / gridColumns=5` → 3×5 by accident — relying on
accident is fragile). Adding explicit `keyRows` removes the inference, and
`touchZoneCount` disambiguates AKP05's 4-zone strip from AKP815's single
800×480 strip.

Output:

- `DeviceDescriptor` carries 4 new fields (`keyRows`, `touchZoneCount`,
  `mainScreenWidthPx`, `mainScreenHeightPx`) — all `std::uint8_t` /
  `std::uint16_t` with zero defaults per RESEARCH.md §6.
- The two helper functions (`akp153_descriptor`, `akp03_descriptor`) and the
  inline AKP05/N4/AKP05E rows in `register.cpp` set the new fields.
- AKP815 row left at `keyRows = 0` (sentinel; D-13).
- A new Catch2 test `test_streamdeck_register_geometry.cpp` iterates the
  registry and asserts the invariant.

This plan can run in parallel with Plan 26-03 (different files; no overlap).
</objective>
