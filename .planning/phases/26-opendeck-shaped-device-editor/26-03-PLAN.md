<objective>
Extend the core `Profile` schema with a `TouchZoneBinding` struct and a
`Profile::touchZones` map (D-11), bump the on-disk JSON schema to v2 with
auto-migrate on load (D-12), and add a corresponding Q_INVOKABLE
`commitTouchZoneBinding` on `ProfileController` that the new
`TouchStripLane.qml` zone delegates (Plan 26-04) will call when an action
is dropped on a touch-strip zone.

Purpose: REQ-26-B requires the touch-strip-zone cells in `DeviceView.qml`
to be distinct drop targets. The drag-drop handler dispatches to
`ProfileController.commitTouchZoneBinding(...)`; that method needs a
storage shape. Per D-11 we choose a NEW `Profile::touchZones` map (cleaner
type signatures, explicit semantic separation) over reusing
`Profile::keys` at offset — the on-disk schema therefore bumps to v2.
Per D-12 the bump is auto-migrating: existing v1 profiles silently load
with empty `touchZones`. The COD-031 boundary is preserved: the
serialiser remains hand-rolled `std::ostringstream` JSON — no
`nlohmann::json` in `ajazz_core`.

Output:

- `src/core/include/ajazz/core/profile.hpp`: `TouchZoneBinding` struct +
  `Profile::touchZones` map.
- `src/core/src/profile.cpp`: `writeTouchZoneBinding` helper following the
  existing `writeEncoderBinding` shape; `profileToJson` emits
  `"_schemaVersion": 2` and a `"touchZones": { ... }` block;
  `profileFromJson` tolerates v1 (no `_schemaVersion`) and reads
  `touchZones` only when present.
- `tests/unit/test_profile_serialization.cpp` extended with:
  (a) a v1-loads-as-v2-empty migration test;
  (b) a v2 round-trip test for `touchZones`.
- `src/app/src/profile_controller.{hpp,cpp}`: a new
  `Q_INVOKABLE void commitTouchZoneBinding(int, QString, QString, int, QString)`
  following the exact shape of `commitKeyBinding`.

This plan can run in parallel with Plan 26-02 (no file overlap).
</objective>
