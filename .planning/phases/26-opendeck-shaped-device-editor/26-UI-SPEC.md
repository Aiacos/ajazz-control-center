| Token | QML Token         | Value | Usage in Phase 26                                                                 |
| ----- | ----------------- | ----- | --------------------------------------------------------------------------------- |

## Color

All from `Theme.qml`. No hard-coded hex in Phase 26 code.

| Role                    | Token                            | Dark-theme Hex (reference) | Usage                                                                                   |
| ----------------------- | -------------------------------- | -------------------------- | --------------------------------------------------------------------------------------- |
| Dominant surface (60%)  | `Theme.bgBase`                   | ~`#14141a`                 | Main content area behind DeviceView; ActionLibraryPane background                       |
| Secondary surface (30%) | `Theme.bgSidebar` / `Theme.tile` | ~`#1e1e23` / derived       | ActionLibraryPane tile rows; outline-frame fallback chassis background                  |
| Accent (10%)            | `Theme.accent`                   | brand blue (Branding)      | Focus rings; selected-cell border; drop-accept highlight; drag-over scale feedback tint |
| Destructive             | `Theme.errorAccent`              | `#e34c4c`                  | Trash drop-zone active highlight; clear-binding confirmation                            |

Accent is reserved for:

- Active focus ring on any interactive cell (`border.color: Theme.accent` when `activeFocus`)
- Selected cell outline (`selected` state on `KeyCell.qml`)
- Drop-accept visual (see Component States below)
- Trash zone highlight during drag

`Theme.tile` / `Theme.tileHover` are the idle/hover cell backgrounds (already
used by `KeyCell.qml:42-43` — reuse without change).

`Theme.borderSubtle` is the idle cell border.

Photo background strategy (D-04, D-07):

- Per-SKU vendor photo loads from `resources/device-photos/<codename>.png`.
  Photo is displayed as-is at native colours; no theme filter applied in v1.
  This is documented as a known light/dark mismatch (vendor photos on white
  background may clash on dark theme). The outline-frame fallback (D-07)
  is theme-aware and uses `Theme.tile` as chassis background with
  `Theme.borderSubtle` as the border.
- Light/dark photo polish is explicitly deferred (CONTEXT.md `<deferred>` section).

### New Components

#### `DeviceView.qml`

Top-level device-shaped editor. Replaces `KeyDesigner.qml` for all LCD-key SKUs.

**Layout:**
Three-column `RowLayout`:

1. `ActionLibraryPane.qml` — fixed 240px wide (matches OpenDeck's 288px scaled down for our compact window)
1. Device chassis area — fills remaining width; houses photo/outline-frame background with overlaid cell grid
1. `Inspector.qml` — fixed 280px wide (existing right-pane contract preserved)

Device chassis area composition:

- When photo available: `Image { fillMode: Image.PreserveAspectFit }` at the
  layout-JSON viewBox aspect ratio, overlaid by an `Item` that positions
  cells at viewBox-relative coordinates scaled uniformly to the rendered photo size.
- When photo missing (D-07 fallback): a `Rectangle` with `color: Theme.tile`,
  `border.color: Theme.borderSubtle`, `radius: Theme.radiusLg`, and a
  `layer.effect: MultiEffect { shadowEnabled: true; ... }` matching
  `Theme.elevation2`. Cells are placed in a `Grid` layout using
  `Theme.spacingSm` column/row spacing.

**Overflow handling:** If `max(keyColumns, encoderCount, touchZoneCount) > 8`
OR total rows > 4, wrap the chassis area in a `Flickable` with `clip: true`
and fade edges with a `ShaderEffect` mask gradient on the chassis boundary.
This matches the OpenDeck overflow rule from `DeviceView.svelte:76-77`.

**Three-row stack (OpenDeck pattern):**

```
Row 1..keyRows:   Repeater over (keyRows × keyColumns) → KeyCell.qml (extended)
Row keyRows+1:    (visible when encoderCount > 0) Repeater over encoderCount → EncoderDial.qml
Row keyRows+2:    (visible when touchZoneCount > 0) Repeater over touchZoneCount → TouchStripLane zone cells
```

**Row spacing:** `Theme.spacingLg` (16px) between the three rows.

#### `EncoderDial.qml`

Round encoder cell. Drag-drop target AND source when occupied.

**Visual spec:**

- Shape: full circle (`radius: width / 2`)
- Size: derived from layout JSON `w` / `h` fields (viewBox-scaled). Minimum
  visual size 60×60; minimum touch target `Theme.minTouchTarget` (44px, but
  dial is always >= 60 so this is always satisfied).
- Background: `Theme.tile` idle, `Theme.tileHover` on hover — matches `EncoderCard.qml`
- Border: 2px `Theme.accent` always visible (reuses existing `EncoderCard.qml` pattern — border.color: Theme.accent)
- Focus ring: `Theme.focusRingWidth` (2px) `Theme.accent` border when `activeFocus`
- Content: Material Symbols icon `tune` (generic encoder icon) OR user-assigned icon
  centered at 28px. Label text below icon at `Theme.typeLabelMedium` (12px / 500).
- Icon colour: `Theme.fgPrimary` at 70% opacity when idle; 100% when hovered/focused.

**States:** See Component States table below.

#### `TouchStripLane.qml`

Horizontal lane of `touchZoneCount` LED-bar cells. Each cell is a discrete
drop target (not one wide cell).

**Visual spec per zone cell:**

- Shape: rectangle with `radius: Theme.radiusSm` (4px)
- Size: derived from layout JSON; aspect ratio approximately 3:1 (wide bars).
  Minimum touch target height `Theme.minTouchTarget` (44px).
- Background: `Theme.tile` idle, `Theme.tileHover` on hover
- Border: 1px `Theme.borderSubtle`; top border thickened to 4px `Theme.accent` at
  the top edge to hint at the LED-strip nature (matches OpenDeck `Key.svelte:225-227`).
- Content: Material Symbols icon `view_column` (touch-strip hint icon) centered
  when empty; user-assigned icon fills the cell when occupied.
- Icon + label rendering: same rules as `KeyCell.qml` (icon fills, label overlaid
  at bottom with `Text.Outline` style shadow for legibility).

**Lane layout:** `Row { spacing: Theme.spacingXs }` with cells in order 0..touchZoneCount-1.

#### `ActionLibraryPane.qml`

Left-panel drag-source library. 240px fixed width.

**Visual spec:**

- Background: `Theme.bgBase`
- Pane header: "Actions" label at `Theme.typeTitleSmall` (14px / 500),
  `Theme.fgPrimary`, `Theme.spacingLg` (16px) padding horizontal,
  `Theme.spacingMd` (12px) padding vertical.
- Divider below header: 1px `Theme.borderSubtle`
- Tile list: `ListView` with `spacing: 0`; each tile is an `ItemDelegate`

**Per-tile (action row) spec:**

- Height: 48px (comfortable list density; slightly above `Theme.minTouchTarget`)
- Padding: `Theme.spacingLg` (16px) horizontal, `Theme.spacingMd` (12px) vertical
- Icon: Material Symbols, 20px, `Theme.accent` colour, left-aligned
- Label: `Theme.typeBodyMedium` (14px / 400), `Theme.fgPrimary`, left of icon
  with 8px gap
- Background: `Theme.bgBase` idle, `Theme.bgRowHover` on hover
- Drag affordance: `cursor: Qt.OpenHandCursor` on `MouseArea` (entire tile is
  draggable; `DragHandler { id: dragHandler; target: null }`)
- During active drag: tile background stays idle (drag visual is the system drag
  image — the ItemDelegate itself)

**ActionKind → Material icon mapping (D-03):**

| ActionKind     | Enum | Icon name     | Accessible label |
| -------------- | ---- | ------------- | ---------------- |
| Plugin action  | 0    | `extension`   | "Plugin action"  |
| Key macro      | 2    | `keyboard`    | "Key macro"      |
| Launch command | 3    | `terminal`    | "Launch command" |
| Open URL       | 4    | `link`        | "Open URL"       |
| Open folder    | 5    | `folder_open` | "Open folder"    |

Source: CONTEXT.md D-03 (Multimedia→`music_note` was mentioned as example; the
actual Inspector.qml enum maps 0=Plugin, 2=KeyPress, 3=RunCommand, 4=OpenUrl,
5=OpenFolder — these exact icons are prescribed here). `Multimedia` is not a
separate ActionKind in the current `Inspector.qml:215-221` model; it is the
user label for ActionKind 2 (key macro that sends media keys). The mapping above
aligns with `Inspector.qml:_kindByIndex` and the ActionKind enum in
`profile.hpp`. If a 6th ActionKind appears, assign `music_note` for multimedia.

## Component States

Every interactive cell (KeyCell, EncoderDial, TouchStripLane zone) supports these
states. States are MUTUALLY EXCLUSIVE in visual priority: selected > drag-over
(accept) > drag-over (reject) > hover > focused > default.

| State              | Visual Treatment                                                                                                                                                                                                | Implementation                                                 |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| Default (empty)    | `Theme.tile` background; `Theme.borderSubtle` 1px border; index number centered in `Theme.fgMuted`                                                                                                              | `KeyCell.qml` existing behaviour                               |
| Default (occupied) | `Theme.tile` background; icon fills cell; optional label overlay                                                                                                                                                | `KeyCell.qml` existing behaviour                               |
| Hover              | `Theme.tileHover` background; no border change                                                                                                                                                                  | `hovered` state                                                |
| Focused (keyboard) | `Theme.accent` `Theme.focusRingWidth` (2px) border; `Theme.tileHover` background                                                                                                                                | `activeFocus` state                                            |
| Selected           | `Theme.accent` 2px border; `Theme.tileHover` background; `selected` property true                                                                                                                               | `selected` property on `KeyCell.qml:35`                        |
| Drag-over (accept) | Scale: 1.05× on both axes, easing `Easing.OutQuad`, duration 100ms. Border: `Theme.accent` 2px. Background: `Theme.surfaceContainerLow` (accent-tinted). Drop-cursor: `Qt.CopyDropAction` / `Qt.MoveDropAction` | `DropArea { onEntered: ... }` + `Behavior on transform.xScale` |
| Drag-over (reject) | No scale. Border: `Theme.errorAccent` 1px dashed (Qt.DashLine). Background unchanged. Drop-cursor: `Qt.IgnoreAction`                                                                                            | `DropArea { onEntered: drop.accepted = false }`                |
| Disabled           | Opacity 0.38 (M3 disabled state). `cursor: Qt.ForbiddenCursor`. Not a drag target.                                                                                                                              | `enabled: false`                                               |

**Scale animation spec (D-10):**

```qml
transform: Scale {
    id: cellScale
    origin.x: width / 2
    origin.y: height / 2
    xScale: 1.0
    yScale: 1.0
    Behavior on xScale { NumberAnimation { duration: 100; easing.type: Easing.OutQuad } }
    Behavior on yScale { NumberAnimation { duration: 100; easing.type: Easing.OutQuad } }
}
```

Scale returns to 1.0 on `DropArea.onExited` and `DropArea.onDropped`.
Neighbouring cells do NOT reflow during scale (D-10 constraint): cells use
absolute positioning within the viewBox-scaled Item, not a Qt Layout.

**Drag-source cursor:**

- Empty cell: `Qt.ArrowCursor` (not draggable)
- Occupied cell: `Qt.OpenHandCursor` when idle, `Qt.ClosedHandCursor` during drag

## Drag-Drop Grammar

Source: D-09 (CONTEXT.md), RESEARCH.md §2.4 + §7.2.

### MIME data shapes

All MIME keys use the `application/x-ajazz-` namespace to avoid collisions
with system clipboard content.

| Drag source            | MIME key                      | Payload                                                                |
| ---------------------- | ----------------------------- | ---------------------------------------------------------------------- |
| ActionLibraryPane tile | `application/x-ajazz-action`  | `JSON.stringify({ actionKind: int, label: string, iconName: string })` |
| Occupied cell (move)   | `application/x-ajazz-binding` | \`JSON.stringify({ controller: "Keypad"                                |

### Drop target rules

| Target cell                     | Accepts from library               | Accepts from cell                         | Swap behaviour                    |
| ------------------------------- | ---------------------------------- | ----------------------------------------- | --------------------------------- |
| KeyCell (Keypad)                | Yes — `application/x-ajazz-action` | Yes — only from `controller: "Keypad"`    | If target occupied: SWAP bindings |
| EncoderDial (Encoder)           | Yes — `application/x-ajazz-action` | Yes — only from `controller: "Encoder"`   | If target occupied: SWAP bindings |
| TouchStripLane zone (TouchZone) | Yes — `application/x-ajazz-action` | Yes — only from `controller: "TouchZone"` | If target occupied: SWAP bindings |

Cross-controller drags (e.g. Keypad → Encoder) are rejected (drop-reject state,
`drop.accepted = false`). This matches D-09's "MIME controller" discriminator
and the SPEC boundary "cell-to-cell within the same controller surface".

### Trash zone (D-09, visual treatment resolved here)

**Treatment:** An icon-button (`RoundButton` with Material Symbols icon `delete`,
`Theme.errorAccent` colour) positioned in the top-right corner of the chassis
area. Visible always but at 30% opacity when no drag is active. On `DragArea`
start (any cell drag begins), the trash zone animates to 100% opacity in 150ms
(`Theme.durationShort`). On `DragArea` end, fades back to 30% in 150ms.

During drag-over the trash zone: icon pulses to `Theme.errorAccent` fill,
background becomes `Theme.chipBgError`, scale 1.1× same 100ms `Easing.OutQuad`.

On drop to trash: `ProfileController.clearBinding(controller, position)` fires.
No confirmation dialog (single-step clear; Revert button in the apply-footer
provides the undo path).

Accessibility: `Accessible.role: Accessible.Button`,
`Accessible.name: qsTr("Clear binding")`, always reachable via keyboard Tab
(never `enabled: false`; opacity changes only).

## Layout Grammar

Source: D-01 (CONTEXT.md).

```
MainWindow ─ RowLayout
├── Sidebar         (fixed ~320px — existing DeviceList.qml, UNTOUCHED)
└── ProfileEditor   (fills remaining width — existing, MODIFIED)
    └── Keys tab Loader
        └── DeviceView.qml          (NEW — replaces KeyDesigner.qml for LCD-key SKUs)
            ├── ActionLibraryPane   (240px fixed; left)
            ├── Chassis area        (fills remaining; center — photo or outline-frame)
            │   ├── Device photo or outline-frame Rectangle
            │   ├── Key grid cells  (absolute-positioned in viewBox-scaled Item)
            │   ├── Encoder dial row (absolute-positioned)
            │   ├── Touch-strip zone row (absolute-positioned)
            │   └── Trash zone button (top-right corner of chassis)
            └── Inspector.qml       (280px fixed; right — existing, REUSED)
```

Column minimum widths: ActionLibraryPane 200px, chassis 300px, Inspector 240px.
Total minimum window width for the editor: 320 (sidebar) + 200 + 300 + 240 = 1060px.
If window is narrower than 1060px, ActionLibraryPane collapses to icon-only mode
(24px wide; hover expands to a popover). Inspector collapses below the chassis
(vertical stack). Responsive breakpoints:

- > = 1060px: three-column layout (library | chassis | inspector)
- 760px–1059px: library icon-strip (24px) + chassis + inspector stacked vertically
- < 760px: library hidden (accessible via a "+" button); inspector hidden (accessible
  via cell selection popover). Minimum viable: chassis only.

## Keyboard Navigation

Source: OpenDeck `DeviceView.svelte:83-156` + RESEARCH.md §2.2 + WCAG 2.1.

The device chassis presents as `role="grid"` equivalent in QML: `Accessible.role: Accessible.Table`
on the chassis container. Each cell is `Accessible.role: Accessible.Cell`.

| Key                      | Behavior                                                                                                                                                      |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tab                      | Moves focus through ActionLibraryPane tiles, then chassis cells (left-to-right, top-to-bottom, then encoder row, then touch-strip row), then Inspector fields |
| Arrow Up/Down/Left/Right | Within the chassis, moves focus between cells in the heterogeneous grid (rows modelled as `gridRowLengths` array matching row widths)                         |
| Home / End               | Jump to first / last cell in the current row                                                                                                                  |
| Space / Enter            | Activates the focused cell (selects it; opens Inspector for the cell)                                                                                         |
| Delete / Backspace       | When a cell is focused + occupied: clears the binding (with same result as trash drop; no confirmation)                                                       |
| Escape                   | Deselects current cell; closes any open popover                                                                                                               |

`FocusScope` wraps the chassis area. `KeyNavigation.tab` / `KeyNavigation.backtab`
chain through ActionLibraryPane → chassis → Inspector.

## Photo Background Strategy

Source: D-04, D-05, D-07 (CONTEXT.md).

The device-photo background uses the same `resources/devices/products/`
directory already established by `DeviceImage.qml`. Phase 26 introduces
a SEPARATE directory `resources/device-layouts/<codename>.json` for
cell positioning data and may reuse or extend the existing
`resources/devices/products/product-<codename>.png` photos for the
chassis background display.

Layout JSON schema (D-06):

```json
{
  "codename": "akp05e",
  "photo": "product-akp05e.png",
  "viewBox": { "w": 600, "h": 400 },
  "keys":       [{ "i": 1, "x": 60, "y": 50, "w": 80, "h": 80 }, ...],
  "encoders":   [{ "i": 0, "x": 80, "y": 280, "w": 50, "h": 50 }, ...],
  "touchZones": [{ "i": 0, "x": 50, "y": 340, "w": 120, "h": 40 }, ...]
}
```

Photo load order in DeviceView:

1. Try `resources/device-layouts/<codename>.json` → load `photo` field → load
   `resources/devices/products/<photo>` from qrc.
1. If JSON missing or `photo` field empty: render outline-frame fallback (D-07).
1. If JSON present but photo fails to load: render outline-frame fallback.
1. Never show a broken-image icon. Always fall back silently.

The outline-frame fallback renders cells in a simple `Grid` layout derived
from `DeviceDescriptor` fields (`keyRows`, `keyColumns` inferred from
`keyCount / gridColumns`, `encoderCount`, `touchZoneCount`). The grid uses
fixed 96×96 cells (same as existing `KeyCell.qml` width/height) and
`Theme.spacingSm` (8px) spacing.

From `CLAUDE.md` "Qt 6 / QML gotchas" — all must be respected in Phase 26 code:

1. **`QML_SINGLETON` requires `qmlRegisterSingletonInstance`** — if `DeviceLayoutLoader`
   becomes a QML singleton, pair it with `static_assert(!std::is_default_constructible_v<T>)`.
   Do NOT use bare `QML_SINGLETON` macro path.

1. **`MultiEffect.maskSource` needs a proper Item type** — the outline-frame
   fallback drop-shadow uses `MultiEffect { shadowEnabled: true }` where the
   `source:` is the chassis `Rectangle`. Do NOT attach `MultiEffect` to a bare
   `Rectangle` used as a maskSource; wrap it in an `Item`.

1. **Material attached properties don't cross Popup scope** — if any Popup is
   used (e.g. for a drag-source preview or tooltip), set Material properties
   inside the popup's `contentItem`, not on the popup root.

1. **`DragHandler` + `ListView` flick conflict** — `ActionLibraryPane` uses a
   `ListView`. The `DragHandler` on each tile MUST set
   `acceptedButtons: Qt.LeftButton` and `dragThreshold: 8` to prevent accidental
   drag during list scroll. Source: RESEARCH.md §7.2 Risk item 8.

1. **ASCII-only test names** — any Catch2 `TEST_CASE` or QML test name
   introduced in Phase 26 MUST use ASCII only (no em-dash, arrows, special
   characters). Source: `CLAUDE.md` "Test names must be ASCII-only".
