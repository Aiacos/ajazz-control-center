<objective>
Cover REQ-26-B with two offscreen-QML Catch2-driven test files that
exercise DeviceView.qml's geometry rendering (three SKU classes:
AKP05E 5×2 + 4 + 4, AKP153 3×5 + 0 + 0, AKP03 2×3 + 3 + 0) and the
drag-drop wire from ActionLibraryPane tiles onto each cell type
(KeyCell → commitKeyBinding, EncoderDial → commitEncoderBinding,
TouchStripLane zone → commitTouchZoneBinding).

Purpose: REQ-26-B's acceptance criteria explicitly call out an offscreen
QML test ("validated by QML offscreen test with synthetic AKP05E
descriptor"). This plan lands those tests. The plan also resolves
RESEARCH.md §8 risk 7 (DragHandler + ListView conflict — covered by an
assertion that ActionLibraryPane tile drag begins only after the 8px
threshold is exceeded).

The QML offscreen harness `tests/qml/ajazz_qml_tests` has a pre-existing
LINK ISSUE per CLAUDE.md "Latent items" (`PluginDeviceBridge::on*`
undefined refs in `application.cpp.o`). This plan handles that two ways:
(1) attempt to fix the link by ensuring the test target links the same
sources used by the live app, or (2) introduce a SLIMMER test target
that only links the bare minimum (DeviceView.qml + KeyCell.qml +
EncoderDial.qml + TouchStripLane.qml + ActionLibraryPane.qml + a stub
ProfileController), avoiding the broken PluginDeviceBridge link path
entirely. The executor picks whichever path takes less context and
documents the choice in the SUMMARY.

This plan runs in parallel with Plan 26-06 (different files; no overlap).
</objective>

tests/qml/test_qml_smoke.cpp — the existing smoke test that instantiates QML on the offscreen platform. The pattern: Catch2 driver + QQmlApplicationEngine + offscreen QPA + a small QML inline component.

QML test approach options (planner picks one in the action block):
A. Inline QML strings inside the C++ test driver (test_qml_smoke.cpp-style).
B. Separate .qml test files loaded by the C++ driver via setSource.
C. Qt Test (QtTest module) `tst_*.qml` files run via the qmltestrunner.

Existing CLAUDE.md note: tests/qml has a pre-existing link issue. The Phase 26 plan picks one of:

- Slimmer target: a new CMake target `ajazz_qml_devview_tests` that links only the QML files + a stub ProfileController shim + a stub DeviceModel shim. Avoids the broken PluginDeviceBridge dependency.
- Link fix: add the missing `PluginDeviceBridge::on*` sources to the existing `application.cpp.o` link path so the existing target builds.

Test scenarios:

1. test_device_view_geometry.qml (REQ-26-B geometry):

   - For each of (AKP05E, AKP153, AKP03):
     - Construct a fake DeviceDescriptor JS object with the right keyCount/keyRows/gridColumns/encoderCount/touchZoneCount.
     - Instantiate `DeviceView { keyCount: ...; keyRows: ...; gridColumns: ...; encoderCount: ...; touchZoneCount: ...; codename: "akp05e"|"akp153"|"akp03" }` in a hidden QQuickItem.
     - Assert via findChildren or via a `function countKeyCells()` helper exposed on DeviceView (or via inspecting `keyRepeater.count`) that the correct number of LCD-key cells, encoder dials, touch-zone cells exist.
     - Specifically: AKP05E → 10 KeyCell + 4 EncoderDial + 4 TouchZone; AKP153 → 15 KeyCell + 0 EncoderDial + 0 TouchZone; AKP03 → 6 KeyCell + 3 EncoderDial + 0 TouchZone.

1. test_device_view_drag_drop.qml (REQ-26-B drag-drop):

   - Use a Qt Test QML `MouseDragHelper` or synthesise the drag programmatically via the QML `Drag` attached property and a simulated DropArea.onDropped invocation.
   - Inject a stub `ProfileController` that records calls to commitKeyBinding/commitEncoderBinding/commitTouchZoneBinding in arrays accessible from the test.
   - For each commit method, simulate a drag from an ActionLibraryPane tile (model.kind=4 "Open URL") onto a target cell and assert the corresponding array now contains the expected call. Assert cross-controller drops are REJECTED (e.g. simulating a binding-MIME drag from an EncoderDial onto a KeyCell does NOT call commitKeyBinding).

The stub ProfileController is a small C++ shim that exposes the same Q_INVOKABLE signatures but records calls in QVariantList properties readable from QML. Alternative: pure-QML stub with the same signal/method surface (no C++ involved). Pick whichever is simpler.

Test names ASCII only (CLAUDE.md). Tags `[qml][device_view][geometry]` and `[qml][device_view][drag_drop]`.
