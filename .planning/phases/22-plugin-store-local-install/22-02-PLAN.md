Implement `installFromFile` in the .cpp following RESEARCH Pattern 1 (verify-before-trust):

1. Read the file capped at `kMaxPluginDownloadBytes`; run `validateDownloadedArchive(body)` —
   on error, `installFinished(path, false, err)`, return false.
1. `extractSdPluginArchive(localPath, <stagingDir>, <subdir>)` into a STAGING dir under
   `userPluginsDir()` (a sibling temp/staging dir, NOT `installedPlugins/` — RESEARCH anti-pattern:
   never extract straight into the discoverable dir). On extract failure → `installFinished(false)`.
1. `verifyStagedPlugin(<stagingDir>/<subdir>/manifest.json)`:
   - `Refused` (tampered OR unsigned): quarantine/remove the staging dir, `installFinished(path, false, outcome.reason.isEmpty() ? tr("signature verification failed") : outcome.reason)`,
     return false. **Tampered is ALWAYS refused.**
   - `SelfSigned`: this is the developer-sideload case. POLICY (Claude's discretion — pick the safer
     default that still permits sideload): allow promotion ONLY when an explicit-confirm flag is set
     (add an optional `bool userConfirmedUnsigned = false` param OR a separate
     `Q_INVOKABLE bool confirmInstallFromFile(QString path)` that the QML warning dialog calls).
     Without confirmation, return a distinct `installFinished(path, false, tr("self-signed plugin — confirm to install"))` so the QML can show the warning + confirm affordance. Document the
     chosen shape in the SUMMARY.
   - `Trusted`: promote directly.
1. Promote: atomic-rename the staging subdir into the Phase-18 `installedPlugins/` layout (per
   22-01-SUMMARY) so discovery finds it. Then flip `m_install[key].installed/enabled`, emit
   `dataChanged` + `installedCountChanged` + `installFinished(path, true, "")`. Use
   `verdictToTrustLevel` for the log line.
