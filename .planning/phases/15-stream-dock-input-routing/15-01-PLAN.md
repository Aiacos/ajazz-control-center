<objective>
Build the app-layer `StreamDockInputService`: the first instantiation of the core
`ActionEngine` in the app, and the device-event -> binding -> execution path that
Phases 16/19 reuse. A QTimer pumps `poll()` on a held `shared_ptr<IDevice>`; the
registered `onEvent` callback maps each decoded `DeviceEvent` to the bound action
chain in the active `Profile` and runs it through one `ActionEngine` constructed with
the app's `ActionExecutors` (keyPress / runCommand / openUrl real; plugin a logged
Phase-19 stub) and the injected `QtExecutor` (so Sleep never blocks the poll thread).
Adds the 16 ms rotation coalescer, encoder press->synthetic-release pairing, and the
provisional touch X->zone derivation (INPUT-03/04/05).

Purpose: The device backend already fully decodes input (`Akp05Device::poll()` ->
`parseInputReport` -> `DeviceEvent` -> `onEvent`), but NO app code consumes it
(`grep ->poll()/onEvent src/app/` == 0 hits). This plan is the app-layer glue that
turns a physical press/turn/tap into an executed action chain — the load-bearing reuse
surface for Phase 16 (controls/persistence/pages), Phase 19 (plugin bridge, which adds a
second event consumer and wires the plugin executor), and the family.

Output: new `stream_dock_input_service.{hpp,cpp}`, a CMake source/AUTOMOC entry, and a
MockTransport-fed unit test that is the hardware-free gating proof (live encoder/touch on
the AKP05E deferred to Phase 25). This plan does NOT wire Application — that is Plan 15-02.
</objective>
