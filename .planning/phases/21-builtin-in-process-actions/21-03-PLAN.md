<objective>
Land the dispatch core that makes the built-in UUIDs work in-process: a pure-core
`BuiltinActionRegistry` (UUID -> handler dispatch table, no Qt/nlohmann) and an app-tier
`BuiltinActionsService` that builds the registry and supplies the Qt/OS-touching handlers for the
LOCKED core set - page nav (previous/next/goto/indicator/change), profile nav
(openchild/backtoparent/rotate), `device.brightness` (Phase-14/16 control service `setBrightness`),
`system.hotkey`/`plain.text`/`system.multimedia`/`system.volume` (the 21-01 `IInputSynthesizer`),
`browser` (the Phase-15 `openUrl` executor), `multiactions` + `multiactions.LunBo` (the
`ActionEngine.run` chain walk + a per-key cursor), and `obsstudio` (the 21-02 `ObsClient`,
auth default-on). The app's `plugin` executor short-circuits a registered built-in UUID to the
registry BEFORE the Phase-19 plugin-host path - in-process, no plugin spawn. The opt-in global-hook
CAPTURE stays OFF unless a settings toggle is set.

This plan is Wave 2: it depends on 21-01 (the `IInputSynthesizer` for synthesis) and 21-02 (the
`ObsClient` for obsstudio). The STOP gate for 15/16/19 was performed by 21-01; this plan reads the
recorded seam signatures from 21-01-SUMMARY (the keyPress/plugin executor stub the app replaces, the
Phase-16 page-nav owner + repaintPage, the bridge presence) plus 15-02/16-03 SUMMARY files directly.

Purpose: PLUGIN-12 - the dispatch table + the per-UUID handler wiring that turns a built-in binding
into an in-process action; this is overwhelmingly wiring existing machinery (control service,
ActionEngine chain walk, page carousel, openUrl, the new synthesizer + OBS client) to new UUIDs.
Output: `builtin_action_registry.{hpp,cpp}` (core) + `builtin_actions_service.{hpp,cpp}` (app) +
Application wiring of the plugin-executor short-circuit + the hardware-free spy/fake test.
